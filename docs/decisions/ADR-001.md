# ADR-001: Centralize Business Rules and Authorization in the Application Layer
## Status
Accepted

## Context
The Internal Operations Service Hub allows employees to submit and track internal service requests, while authorized department staff handle and update those requests.
The system requires consistent validation, authorization, request handling, status tracking, ownership management, and approval-related behavior.
The User Interface is considered an untrusted boundary and should not be responsible for enforcing critical business or authorization rules.

## Decision
Business rules, validation, and authorization checks will be enforced by the Application Layer.
The User Interface will be responsible for user interaction and sending actions to the Application Layer, but it will not be trusted to enforce critical system rules.
The Application Layer will validate requested actions before reading or modifying durable system data.

## Consequences
### Positive
- Business rules are enforced consistently in one trusted layer.
- Authorization does not depend on client-side behavior.
- Different user interfaces can rely on the same application rules.
- Request state and ownership changes can be validated before they are persisted.
### Trade-offs
- The Application Layer becomes a critical part of the system.
- Business rules must be maintained consistently as requirements evolve.
- User actions require communication between the User Interface and the Application Layer.

## Related Requirements
This decision supports:
- Secure and authorized access to internal requests.
- Clear request ownership.
- Reliable request status and progress updates.
- Consistent handling of Service Requests.
